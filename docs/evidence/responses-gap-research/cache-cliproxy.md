# CLIProxyAPI cache-affinity audit

This is a narrow source audit of current `router-for-me/CLIProxyAPI` main at [`61fdfc341b96178a8dcb53f2efc46cbc341d267c`](https://github.com/router-for-me/CLIProxyAPI/commit/61fdfc341b96178a8dcb53f2efc46cbc341d267c), inspected 2026-09-20 (commit dated 2026-09-19). It separates prompt-cache affinity, sticky credential selection, Responses usage accounting, and encrypted-reasoning replay. It does not treat those as one cache.

## What CPA's request helper actually does

For Codex OpenAI Chat Completions and Responses requests, `cacheHelper` primarily **chooses and injects an affinity ID**. If the source is Chat Completions, it prefers caller `prompt_cache_key`; otherwise it derives a provider-scoped UUID from execution-session or derived-session metadata; if neither exists, it falls back to a deterministic UUID derived from the gateway API key. For Responses source, it uses caller `prompt_cache_key` when present, then the same metadata fallback. It writes the chosen value into the upstream JSON `prompt_cache_key` and sets HTTP `Session-Id` to the same value. See [ID selection and request construction](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/internal/runtime/executor/codex_executor_request.go#L99-L155) and [provider UUID derivation](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/internal/runtime/executor/helps/derived_session.go#L14-L46).

There is no local prompt-token or prefix-content store in the OpenAI/Responses branches of this helper. The `ClaudeCodePromptCache` call is a separate Claude-source branch. CPA's actual prompt KV cache is upstream behavior, inferred by the proxy from upstream usage fields; writing a key only supplies an affinity signal. This helper is also separate from CPA's encrypted-reasoning replay cache, which retains selected reasoning items for a later request and does not implement full response-ID storage/replay. The ordinary HTTP executor still removes `previous_response_id` before posting its request ([request rewrite](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/internal/runtime/executor/codex_executor_execute.go#L59-L65)).

The IDs are chosen differently by transport:

- **HTTP/SSE:** cache key is inserted in the body and sent in the `Session-Id` header. CPA's current unit test explicitly expects `Conversation_id` and legacy `Session_id` to be absent in this path ([test](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/internal/runtime/executor/codex_executor_cache_test.go#L20-L71)).
- **WebSocket:** CPA inserts the same key in the body, `session_id`, and `Conversation_id`; its header helper removes the hyphenated `Session-Id` ([WS key mapping](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/internal/runtime/executor/codex_websockets_request.go#L21-L64), [header selection and casing](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/internal/runtime/executor/codex_websockets_request.go#L151-L175)).

The identity used for **auth routing** is related but not identical to the prompt-key helper. Current session extraction recognizes `Session-Id`/`Session_id` and `Thread-Id`/`Thread_id`; body extraction recognizes `prompt_cache_key` before `conversation.id` ([Codex extraction](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/sdk/cliproxy/session/info.go#L236-L276), [body key precedence](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/sdk/cliproxy/session/info.go#L735-L779)). This can make routing recognize an explicit session field that the prompt-key helper itself does not read directly.

## Derived keys can fragment batch prefix caching

When the request has no explicit session signal, the conductor runs the session enricher before selection/execution ([entry point](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/sdk/cliproxy/auth/conductor_execution.go#L121-L123)). Its derived root includes source format and caller scope, and hashes the leading instructions plus the first complete user input; the instruction contribution is truncated to 50 Unicode runes ([identity derivation](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/sdk/cliproxy/session/identity.go#L489-L527), [Responses and Chat root extraction](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/sdk/cliproxy/session/identity.go#L530-L586), [50-rune truncation](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/sdk/cliproxy/session/identity.go#L20-L24), [application](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/sdk/cliproxy/session/identity.go#L681-L697)). CPA then converts that derived identity into a stable provider UUID and uses it as `prompt_cache_key` ([mapping](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/internal/runtime/executor/helps/derived_session.go#L24-L46), [Chat helper branch](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/internal/runtime/executor/codex_executor_request.go#L122-L140)).

That is a useful heuristic for repeated turns whose first user message stays the same. It can be counterproductive for independent batch calls that share a long system prefix but have different first user messages: each call gets a different affinity key even while much of the prompt prefix is reusable. Open issue [#5300](https://github.com/router-for-me/CLIProxyAPI/issues/5300), still open when checked, reports author-measured cached tokens of `0` then `1792`/`1792` for a fixed caller key, but `0`/`1792`/`0` without one, and a 0.4% production hit rate for a batch workload. Those are report-specific results, not a guarantee about other accounts/models. The failure mode is consistent with the current derived-root code.

There is a source/issue discrepancy worth preserving: #5300's workaround text also lists explicit `session_id`, `conversation_id`, or a `Session-Id` header as being used verbatim for the prompt key. In the current OpenAI Chat helper, only body `prompt_cache_key` is read directly; the fallback checks execution-session/derived metadata and then gateway API key, not the canonical-session metadata field ([current helper](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/internal/runtime/executor/codex_executor_request.go#L122-L155), [enricher's explicit-session branch](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/sdk/cliproxy/session/identity.go#L230-L263), [helper precedence](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/internal/runtime/executor/helps/derived_session.go#L29-L36)). A caller-supplied JSON `prompt_cache_key` is directly supported; the issue's broader workaround list is not fully corroborated by current request-construction code.

## Sticky upstream credentials are opt-in

CPA does implement a local session-to-auth binding: the key is namespaced by provider, canonical session ID, and model; an available bound auth is reused even if a higher-priority auth returns, while an unavailable binding falls back and can be rebound ([selector behavior](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/sdk/cliproxy/auth/selector.go#L960-L1109), [result binding updates](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/sdk/cliproxy/auth/selector.go#L1413-L1505)). Bindings use a bounded TTL cache; the documented default TTL is one hour ([cache](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/sdk/cliproxy/auth/session_cache.go#L15-L59), [configuration](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/config.example.yaml#L249-L263)). However, `routing.session-affinity` defaults to `false`, so this protection is not active by default ([config default](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/config.example.yaml#L249-L256)). It is also an auth-routing binding, not prompt-cache storage.

## Codex request identity headers

For HTTP/SSE, CPA forwards an incoming `Version` if supplied, propagates client Codex/session/request headers, and applies a Codex TUI User-Agent fallback. Unless `disable-codex-cloaking` is enabled, it forces `User-Agent: codex-tui/0.154.0 (Mac OS 26.5.2; arm64) iTerm.app/3.6.11 (codex-tui; 0.154.0)` and `Originator: codex-tui`; an incoming `Originator` is copied first but the default cloaking step overwrites it. With cloaking disabled, the copied Originator remains; absent Originator defaults to `codex-tui` only for OAuth auth. ([constants](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/internal/runtime/executor/codex_executor_request.go#L25-L30), [HTTP header rules](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/internal/runtime/executor/codex_executor_request.go#L321-L378), [default cloaking config](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/config.example.yaml#L265-L277)). The WebSocket path separately carries `Version`, User-Agent and Originator ([WS headers](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/internal/runtime/executor/codex_websockets_request.go#L84-L149)).

These are request-shaping and client-identity controls. They do not guarantee cache eligibility or a hit. The request prefix, tools, model, selected upstream account, and upstream cache state can still differ.

## What CPA does with SSE usage

The HTTP execution path consumes Codex SSE and extracts counters only from terminal `response.completed` or `response.incomplete` events; it publishes those to CPA's usage reporter, then translates the response for the downstream format ([terminal SSE handling](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/internal/runtime/executor/codex_executor_execute.go#L133-L199)). The streaming executor likewise parses terminal events while forwarding translated chunks ([stream handling](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/internal/runtime/executor/codex_executor_stream.go#L246-L274), [live stream path](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/internal/runtime/executor/codex_executor_stream.go#L403-L426)).

`ParseCodexUsage` reads `response.usage`: input/output/total counters; cache reads from `input_tokens_details.cached_tokens` (with the prompt-token alias); cache creation from cache-creation/write aliases; and reasoning from output-token detail aliases ([parser](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/internal/runtime/executor/helps/usage_helpers.go#L938-L950), [field mapping](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/internal/runtime/executor/helps/usage_helpers.go#L993-L1068)). A regression test covers cached and cache-write fields ([test](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/internal/runtime/executor/helps/usage_helpers_test.go#L102-L127)). For nonstream Responses JSON, CPA fills absent `input_tokens_details.cached_tokens` and `output_tokens_details.reasoning_tokens` with zero ([normalizer](https://github.com/router-for-me/CLIProxyAPI/blob/61fdfc341b96178a8dcb53f2efc46cbc341d267c/internal/runtime/executor/helps/responses_usage_helpers.go#L10-L107)). That keeps the schema consistent; it cannot create a cache hit or establish why the upstream reported zero.

## Prior issue status and local A/B implication

Issue [#2373](https://github.com/router-for-me/CLIProxyAPI/issues/2373) was closed on 2026-03-29. It documented missing/stale continuity signals and random per-request session UUIDs. Its event history shows closure without a linked commit or pull request, so closure alone is not proof every acceptance item was fixed. Current source now has stable derived identities and key/header propagation, but the still-open #5300 illustrates a remaining workload-specific failure mode.

The team's local A/B reports `cached_tokens` of **1664/1822 only after `session-id` matched the prompt-cache key**. This is consistent with the official [Codex client mapping](https://github.com/openai/codex/blob/b05b3e180b858054f10d242e564fc4707b409e8c/codex-rs/core/src/client.rs#L561-L582) and CPA's explicit `prompt_cache_key` → `Session-Id` rewrite; it is a strong lead for the local adapter, not a guarantee of universal hits. Verify the same upstream account, model, prefix, tools, request body, and key in both arms; compare the actual upstream body/header values and final `response.completed.response.usage` counters. Do not attribute any change to encrypted-reasoning replay or response persistence.
